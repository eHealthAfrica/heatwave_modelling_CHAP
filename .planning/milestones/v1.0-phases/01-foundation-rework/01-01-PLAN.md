  <action>
  In heatwave/auth.py: add `from pathlib import Path` to the imports. Replace the line
  `_LOCAL_KEY_FILE = "keys/service_account.json"` with
  `_LOCAL_KEY_FILE = Path(__file__).resolve().parent.parent / "keys" / "service_account.json"`,
  matching heatwave/config.py's `_CONFIG_PATH` anchoring pattern exactly (both files live at
  `heatwave/*.py`, so the identical `.parent.parent` chain lands at repo root). In the
  `_load_credentials()` function, change the final return statement's call from
  `service_account.Credentials.from_service_account_file(_LOCAL_KEY_FILE, scopes=EE_SCOPES)` to
  `service_account.Credentials.from_service_account_file(str(_LOCAL_KEY_FILE), scopes=EE_SCOPES)`
  — `from_service_account_file`'s signature is typed `filename: str`, so cast explicitly rather
  than relying on Path/os.PathLike duck-typing. Remove `import sys`, `import types`, the comment
  "# geemap imports `blessings`, which fails to import on Streamlit Community / Cloud. Stubbing it
  out before geemap is imported avoids the failure.", and the line
  `sys.modules.setdefault("blessings", types.ModuleType("blessings"))` entirely from auth.py. Do
  NOT change the credential resolution order (Streamlit secrets -> EE_SA_JSON -> local key file) or
  the defensive `try/except` around the Streamlit import inside `_load_credentials()` — both stay
  exactly as they are per D-04. D-04 also requires that no Streamlit import be added anywhere in
  auth.py and that `init_ee()` remain a plain, undecorated function so it stays callable uncached
  from non-Streamlit contexts such as Phase 4's `scripts/run_batch_export.py`.
  In heatwave/__init__.py (currently 0 bytes / empty): add a module docstring reading "heatwave
  package. Stubs out `blessings` before any submodule (or geemap) can import it.", then `import
  sys`, `import types`, then `sys.modules.setdefault("blessings", types.ModuleType("blessings"))`
  at module level, unindented, so it executes the instant anything imports the `heatwave` package.
  </action>
