<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| target week t+k -> label column | the only place future data is allowed to be read is the label |
| config cutoffs -> row membership | split policy decides which rows are held out |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-9-01 | Information disclosure (target leakage) | targets.lead_label | mitigate | label built in one place by integer gather `t + k`; independent date-join test on week_start + 7k days; tail positions NaN, never filled; no shift/rolling in targets.py |
| T-9-01b | Spoofing (label meaning) | heatwave_week definition | mitigate | label uses heatwave_days >= 3 only; test with event_count disagreeing proves heatwave_event_count is not used |
| T-9-02 | Information disclosure (held-out into training) | splits.split_masks / fold_masks | mitigate | membership by target-week index only; 14-week embargo; tests assert max(train target) < min(validate target) - embargo per fold and disjointness |
| T-9-02c | Tampering (calendar edge) | 2020-W53 / 2014-12-29 cutoffs | mitigate | cutoffs are config-validated Mondays; tests pin 2020-W53 -> validate, 2015-W01 -> validate, 2021-W01 -> test |
</threat_model>
