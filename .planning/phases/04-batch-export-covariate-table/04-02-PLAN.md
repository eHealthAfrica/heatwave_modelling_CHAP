<objective>
Extend `heatwave/zonal.py` with CONTEXT.md D-08's small-ward fallback reduction and D-09's provenance
flag, closing the null-value policy item Phase 3 explicitly deferred to this phase.

Purpose: EXPORT-03 requires the covariate table to have "no missing wards, no null aggregates" across
all 4,841 wards. Phase 3's `reduce_to_ward_daily` deliberately emits a null `value` for ward polygons
below Earth Engine's ~0.4% pixel-weight inclusion threshold (documented as a caller obligation in its
own docstring, lines 46-56) and left the policy decision to Phase 4. D-08 resolves it: fall back to a
centroid-point sample so the ward gets a genuine — if lower-fidelity — value, which is different from
both "drop the row" and "pretend it's zero". D-09 requires that choice to be visible to whoever
consumes the CSV.

Scope boundary: this plan verifies the fallback on small synthetic fixtures against live Earth Engine.
It does not run the 4,841-ward small-ward survey — that is a setup step inside the production script
(plan 04-04), executed as part of the separate, manual, hours-long production run.

Output: modified `heatwave/zonal.py`, extended `tests/test_heatwave_detection.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ERA5-Land raster pixels -> per-ward table | Gridded upstream values cross into the tabular representation every downstream aggregate is computed from; a ward whose polygon is sub-pixel is the exact place where "missing" can silently become "zero" |
| Caller-supplied `fallback_ward_ids` -> ward partition filter | The fallback list is an in-repo caller parameter (tests now, `scripts/run_batch_export.py` in plan 04-04) — trusted, internal, not externally submitted, but it directly determines which wards get lower-fidelity data |
| Per-row `used_fallback_reducer` flag -> CSV consumer | The only channel by which a downstream consumer can distinguish primary from fallback data provenance (D-09) |
| Test runner -> GCP service account | `tests/test_heatwave_detection.py` reads `keys/service_account.json` (or `EE_SA_JSON`) and issues live Earth Engine calls against `heatwave-508110` |
