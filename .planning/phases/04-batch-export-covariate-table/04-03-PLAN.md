<objective>
Create `heatwave/export.py` — the weekly covariate aggregation module that turns
`detect_heatwave_events`' per-ward-daily output into the EXPORT-02 covariate table.

Purpose: this is the only genuinely new algorithmic work in Phase 4, and 04-RESEARCH.md's live
session caught two ways of writing it that are **silently wrong** — wrong in a way that looks fine in
a smoke test and only corrupts the data at year boundaries and across group keys:

1. Pairing `ee.Date.get('year')` with `ee.Date.get('week')` produces `2024-W01` for `2024-12-30`,
   which is really `2025-W01`. That splits one real ISO week across two `time_period` buckets, every
   single year, for all 35 years of the backfill (04-RESEARCH.md Pitfall 2, reproduced live).
2. Chaining two `.group()` calls to group by (ward, week) returned output with week and value
   cross-assigned between groups — no error raised, just plausible-looking wrong numbers
   (04-RESEARCH.md Pitfall 4, reproduced live).

Both have verified-correct replacements (the Thursday-of-week formula, and a single composite string
key). This plan implements those, and pins each one with a test that fails if someone later
"simplifies" the code back to the naive form.

Scope boundary: every test here runs on small hand-computable synthetic fixtures against live Earth
Engine, inside the 30-second feedback budget. Nothing in this plan runs the full 1991-present
backfill, and no acceptance criterion depends on `outputs/covariate_table.csv` existing.

Output: `heatwave/export.py`, extended `tests/test_export.py`.
</objective>

Input contract (`build_covariate_table`'s `events_fc`) — exactly `detect_heatwave_events`' output:
```
ward_id            string  ward identifier
value              double  heat index for that ward-day (may be null)
is_hot             int     1 when the day exceeded its threshold, 0 otherwise, null when unjoined
event_id           int     run id of a qualifying event, or NO_RUN (-1)
system:time_start  long    day timestamp in millis
```

Output contract — one feature per (ward, ISO week), properties EXACTLY:
```
time_period            string  "YYYY-Www", zero-padded week   (EXPORT-02)
location               string  the ward id                    (EXPORT-02)
heatwave_days          int     count of is_hot==1 days that week; genuine 0 when none
mean_heat_index        double  mean of value across the week; null when no data (never 0)
max_heat_index         double  max of value across the week; null when no data (never 0)
heatwave_event_count   int     events STARTING that week; genuine 0 when none
```
